## How Parallel Agents Work

You run multiple `claude` sessions simultaneously — each in its own terminal tab or IDE window — all pointing at the same repo. They work on different files so there are no merge conflicts. When one finishes, you commit, and the next agent reads this file to know what's done.

**Daily workflow:**
```
Terminal 1: claude   ← Agent A (e.g. Buyer track)
Terminal 2: claude   ← Agent B (e.g. Backend track)
```
Both read the same codebase. Each writes to its own assigned files. You commit Agent A's work, then Agent B's, no conflicts.

## Key Architecture Decisions

1. **BuyerTabNavigator** is an adaptation of the existing `DrawerNavigator.tsx` MobileNavigator. Copy the MobileTabBar component and 5-tab structure. Swap the "Home" tab target to `LiveDiscoveryScreen`. Rename "Videos" to "Cashback" and point it at `MobileHomeScreen` (the existing deals/cashback feed). Everything else is identical.

2. **SellerTabNavigator** is a fresh 4-tab navigator using the same MobileTabBar design but with `Colors.orange` (`#F97316`) for active state instead of `Colors.primary` (`#4784E2`).

3. **`user.role`** in the Zustand store is already typed as `role?: string`. Update `UserType` to `role?: 'buyer' | 'seller' | 'admin' | null`. The RootNavigator reads this and branches.

4. **LiveDiscoveryScreen** has two toggle pills: "Live" and "Stores". Live tab shows stream cards from `GET /streams/active` + real-time updates via Socket.io. Stores tab renders the existing `OfflineStoresScreen` inline. Followed stores appear first when live.

5. **StoreDetailScreen** gets an `isOwner` prop. When true (seller viewing their own store), it shows Edit controls and links to `MyStoreScreen`. When false (buyer), it shows the Follow button.

6. **Daily.co**: broadcaster calls `POST /streams/token`, gets a Daily.co room URL + token, initialises `DailyMediaView` and `DailyCall`. Viewer calls `POST /streams/:id/viewer-token`, joins as viewer. Both use `@daily-co/react-native-daily-js`.
