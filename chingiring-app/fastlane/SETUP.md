# fastlane — Google Play delivery for Chingiringi (Android)

fastlane here does **one job**: take the signed `.aab` that **EAS Build** produces and
deliver it to Google Play — upload it to a testing track and/or update the store listing
(title, description, screenshots, release notes) through Google's Play Developer API
(`supply` / `upload_to_play_store`).

**fastlane does not build or sign the app** — EAS Build still does that. The binary lanes
(`validate`, `internal`) only ever touch the **internal** track as a **draft**. The
`metadata` lane is the exception: it edits the **public** store listing (Google reviews
changes before they go live).

> This file is the guide. `fastlane/README.md` is auto-generated by fastlane and is
> suppressed here via `skip_docs` in the Fastfile — edit **this** file, not that one.

---

## 1. Install (one time, this machine)

Gems install into a project-local path (`vendor/bundle`) — no `sudo`, nothing touches
system Ruby. This is already configured in `.bundle/config` (which is committed on purpose
so fresh clones vendor gems the same way).

```bash
cd chingiring-app
bundle install
```

Then run every lane through bundler:

```bash
bundle exec fastlane android <lane>
```

> **Ruby:** macOS system Ruby is 2.6, on which Bundler resolved **fastlane 2.230.0** — not
> the current 2.241.x (newer fastlane needs a newer Ruby). 2.230.0 is fine for `supply`. If
> you want the latest fastlane (it carries newer security fixes), that's your call: install
> a modern Ruby (`brew install ruby`, or rbenv), then `bundle update fastlane`. Never
> `sudo gem install`.
>
> **Locale:** if you see a UTF-8 locale warning, `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`
> (add it to your shell profile).

## 2. Google Play service-account key (one time — your Google account)

`supply` authenticates with a **service-account JSON key**. You create this by hand — it's
tied to your Play Console. Steps below follow fastlane's current
[Android setup guide](https://docs.fastlane.tools/getting-started/android/setup/):

1. **Play Console → Account Details** — note the **Google Cloud Project ID** shown there.
2. **Enable the Google Play Android Developer API** in Google Cloud: pick (or create) a
   Google Cloud project that matches that linked project, and press **Enable**.
3. **Create the service account** in Google Cloud →
   [Service Accounts](https://console.cloud.google.com/iam-admin/serviceaccounts) (make sure
   the active project matches the linked one): **Create service account**, give it a name
   (e.g. `fastlane-supply`), **save the generated email**, then press **Done** (skip the
   optional access steps).
4. **Create the JSON key:** on that service account's row → **⋮ Actions → Manage keys →
   Add key → Create new key → JSON → Create**. Save the downloaded file.
5. **Grant access back in the Play Console → Users and Permissions → Invite new users:**
   paste the service-account email, open **Account Permissions**, and grant it access (the
   guide recommends **Admin (all permissions)**; at minimum it needs release-to-testing and,
   for the `metadata` lane, store-presence rights). **Invite user.**
6. Put the key **outside the repo** and point fastlane at it:

   ```bash
   export SUPPLY_JSON_KEY="/absolute/path/to/play-key.json"
   ```

   (Or drop it at `fastlane/play-service-account.json` — that path is gitignored. Keeping it
   outside the repo is safer.)

Verify the key works (uploads nothing):

```bash
bundle exec fastlane run validate_play_store_json_key json_key:"$SUPPLY_JSON_KEY"
```

> **Prerequisite:** the app must already exist in the Play Console with **at least one build
> uploaded manually**. The API can't create an app's very first release, and `supply init`
> (section 5) needs an existing listing.

## 3. Get the `.aab` from EAS

fastlane uploads a local file, so grab the EAS build artifact first. Build with the
`playstore` profile (it's `buildType: app-bundle`):

```bash
eas build --platform android --profile playstore
```

Then either:

- **Dashboard** — open the finished build on expo.dev and **Download** the `.aab`, or
- **CLI** — list recent finished `playstore` builds as JSON and download the one you want:

  ```bash
  eas build:list --platform android --build-profile playstore --status finished \
    --limit 10 --json --non-interactive
  ```

  Pick your build (the list order isn't documented, so don't assume newest-first), find its
  application-archive URL in the JSON (look inside the `artifacts` object — the exact field
  name isn't documented, so confirm it), then:

  ```bash
  curl -L --create-dirs -o build/chingiringi.aab "<that-url>"
  ```

> `eas build:download` is **not** the one to use here — it's scoped to simulator/emulator
> builds, not store `.aab`s. (`build/` and `*.aab` are gitignored.)

## 4. Lanes

The binary lanes take the `.aab` via `aab:<path>` or the `AAB_PATH` env var. Relative paths
are resolved against the **project root** (`chingiring-app/`), e.g. `aab:build/chingiringi.aab`.

| Lane       | What it does                                                                     |
|------------|----------------------------------------------------------------------------------|
| `validate` | Dry run — validates the `.aab` against Play, uploads nothing.                     |
| `internal` | Uploads the `.aab` to the **internal** track as a **draft** (not public).         |
| `metadata` | Pushes **only** the store listing from `fastlane/metadata/android`. **Public** — Google reviews it before it goes live. No binary. |

```bash
bundle exec fastlane android validate aab:build/chingiringi.aab
bundle exec fastlane android internal aab:build/chingiringi.aab
AAB_PATH=build/chingiringi.aab bundle exec fastlane android internal
```

## 5. Store listing (metadata & screenshots)

Pull your current live listing into editable files:

```bash
bundle exec fastlane supply init
```

That writes `fastlane/metadata/android/<locale>/…` (title, descriptions, changelogs). Note
the Play API **can't download existing screenshots/videos**, so add those under the image
folders yourself. Edit, then push listing-only:

```bash
bundle exec fastlane android metadata
```

## Notes & gotchas

- **Binary lanes never publish.** `validate`/`internal` stay on the internal track as drafts;
  promote to production from the Play Console (or add a `promote` lane later).
- **`metadata` is public-facing.** It changes the live store listing (after Google's review).
- **First-ever upload** of a brand-new app must be done manually in the Play Console.
- **Never commit** the service-account key or the `.aab`. `vendor/`, `/build/`, `*.aab`,
  `fastlane/report.xml`, and the key path are gitignored. (`.bundle/config` *is* tracked on
  purpose — it only sets `BUNDLE_PATH` so fresh clones vendor gems without sudo.)
- **CI:** to run a lane in GitHub Actions, add the key as a base64 secret and `bundle exec`
  the lane. Not wired up yet — ask if you want it.
